# Final application improvements

Review date: 6 September 2026.

This pass improves error recovery, navigation responsiveness, account settings, map correctness and recovery from database lock contention. It also adds focused regressions for failures that normal successful playthroughs do not exercise. The changes preserve the existing game rules and database schema.

## Changes

| Area | What changed | Why it matters |
| --- | --- | --- |
| API requests | Each HTTP request has a 15-second deadline covering both the response and its body; a refresh-and-retry sequence can take longer. Network failures, timeouts and HTML/plain-text HTTP errors produce readable messages. Malformed JSON and non-object successful responses are rejected; empty 204 responses are supported. Timeouts and network failures during commands explain that the action may already have completed and advise checking the latest state before retrying. | A disconnected or unhealthy server no longer leaves a command waiting indefinitely or exposes a JSON parser error. Ambiguous failures do not encourage immediately repeating a potentially completed action. |
| Session recovery | Concurrent expired requests still share one refresh operation, and retries keep their original idempotency key. Server clock estimates accept only finite numeric timestamps. The guest guide now correctly describes browser-dependent access instead of claiming a 15-minute guest lifetime. | Error handling preserves the existing protection against duplicate commands, avoids corrupt countdown offsets and gives players accurate account guidance. |
| Reports, messages and rankings | Loading and failed requests receive explicit feedback and a retry control. Empty inbox messages appear after successful requests. | Players can distinguish an empty result from an unavailable server and retry without reloading the game. |
| Actions and feedback | Sign-out, settlement after defeat and read-status actions use the shared action/error handling. Failed actions keep the relevant screen available. A persistent live region keeps error alerts accessible while dialogs are open. | A failed request is visible and recoverable; opening a report does not require its read-status write to succeed. |
| Navigation | Unknown page values fall back to the village overview. Navigation retains other URL options, and current-page buttons expose their state to assistive technology. | Shared links remain usable and options such as the Canvas renderer survive navigation. |
| Rendering and countdowns | The village scene and world map reuse their renders when their props are unchanged. Clock updates run at lower priority and stop when no village is loaded. | Twice-per-second countdown updates no longer repeatedly redraw these expensive views; user navigation can take priority. |
| Mobile navigation | The closed sidebar is hidden from keyboard navigation. Opening it moves focus into the menu, contains keyboard focus, supports Escape, disables background interaction and restores focus when closed. Losing the final village also releases scrolling and clears the menu state before resettlement. | Keyboard and assistive-technology users can operate the narrow layout without moving into covered content or retaining a scroll lock after defeat. |
| Village settings | Switching villages resets the editable name to the selected village. The continent indicator derives from the selected coordinates. | An unsaved name from one village is not presented as the name of another, and the location label stays accurate. |
| Attack alerts | Settings inspect the browser's existing subscription, show checking/enabled/disabled states, support disabling alerts and explain unsupported browsers or denied permission. Worker startup has a deadline, and a newly created subscription is cleaned up if server registration fails. | Alert controls describe the current browser state and give players a usable recovery path when setup fails. |
| Map startup | Map initialization can proceed when the nearby-search request fails, while the search panel shows its error. | The visual map remains usable during a partial API outage. |
| Map tile boundaries | The API calculates the final tile from `ceil(map.size / map.tileSize) - 1`, replacing the fixed maximum of 299. | A valid 30,000-coordinate world with 10-coordinate tiles can load its outer tiles. Negative, fractional and out-of-world tiles remain invalid, and partial final tiles are supported. |
| Database contention | PostgreSQL lock timeout `55P03` joins the transaction helper's existing bounded retry conditions. Each attempt still has a five-second lock timeout, and explicit attempt limits remain in force. | Concurrent joins can recover from temporary world-lock contention. Real-database regressions verify that rollback prevents duplicate charges and post-commit notifications, and that exhaustion remains bounded. |

The API rerun extended only the setup allowance and passed all 20 cases. [Container startup log](../artifacts/final-review/containers.log), [initial full run](../artifacts/final-review/tests.log).
- The concurrent-join failure reproduced independently as PostgreSQL `55P03` at the initial world lock. Adding it to the bounded retry policy resolved that regression. Tests also confirmed rollback of provisional charges, exactly one post-commit notification and bounded exhaustion. [Reproduction](../artifacts/final-review/placement-rerun.log), [successful regression run](../artifacts/final-review/transaction-regressions.log).
- Reusing the API test database exposed NPC assertions that counted old global fixtures. The test now creates its own users and scopes audit/list assertions to its own batch. Final repeatability evidence is recorded in the table above.
- An early browser matrix stopped after **16 passes and 2 Firefox failures**. One showed the URL changing while the previous screen remained visible; the scene/map memoization and lower-priority clock updates address unnecessary redraws, and the same navigation assertion subsequently passed. A later cold guest-entry failure occurred before the watchdog checks: the guest request succeeded after 9.78 seconds, and the village appeared after the assertion deadline, with no JavaScript errors in the trace. The final matrix ran after the build and broad backend checks had finished. [Initial matrix](../artifacts/final-review/browser-matrix.log), [Firefox follow-up](../artifacts/final-review/browser-firefox-fix.log).

## Ideas and next priorities

1. **Resolve large-map performance and complete the existing launch checks.** Diagnose WebKit startup separately from dense-map frame sampling, profile Canvas rendering and measure on the intended hardware. The earlier [verification record](verification.md) still has open sustained-load, stable hardware frame-rate, installed-device push and operator deployment gates. This polish pass does not certify them. Measure the documented arrival workload separately, test installed Android/iOS alerts, and verify real SMTP, public TLS, off-host backups and alert delivery.
2. **Split the large application component by feature.** Extract reports, messages, tribe, settings and navigation into focused modules while keeping shared action/error behavior in one place. This will make future changes easier to review and targeted browser tests easier to maintain. The final main bundle is 794.52 kB (245.00 kB gzip); consider lazy-loading administration, social screens and the simulator, then measure initial loading and recheck the offline shell.
3. **Replace broad `any` API responses with shared types and boundary validation.** Start with game state, villages, reports and messages. Keep runtime validation at the network boundary so a structurally wrong response cannot silently enter the UI.
4. **Finish unread-message filtering as a complete feature.** The common inbox query accepts `unread`, but the messages query does not apply it and the current messages screen has no unread filter. Add the database predicate, a visible control and regressions for received versus sent messages together.
5. **Expand social error coverage.** Missing diplomacy targets currently fall through to a database foreign-key error; return a clear not-found response instead. Reset an officer's role when leaving a tribe for consistent stored state. Existing leadership checks also require tribe membership, so the latter is data cleanup rather than an identified privilege bypass.
6. **Keep failure-path checks in routine verification.** Retain tests for HTML proxy errors, stalled requests, read-status failures and partial map outages alongside successful playthroughs. Exercise account/session behavior across multiple tabs and longer idle periods in a future pass.
7. **Reconcile alert subscriptions when switching accounts.** An existing browser subscription does not establish that its server registration belongs to the currently signed-in player. Add a server-backed status check or an explicit relink flow and test sign-out/sign-in with two accounts on the same device. The current alert status describes browser subscription state.
